# EmailJS Setup Guide

This document explains how to set up email notifications for the IPDC Platform using EmailJS.

## Why EmailJS?

EmailJS is a free service that allows sending emails directly from JavaScript without a backend server:
- ✅ **Free Tier**: 200 emails/month for free
- ✅ **No Backend Required**: Works entirely client-side
- ✅ **Easy Setup**: Simple API integration
- ✅ **Template System**: HTML email templates with variables

## Setup Steps

### 1. Create EmailJS Account

1. Go to [https://www.emailjs.com/](https://www.emailjs.com/)
2. Click "Sign Up" and create a free account
3. Verify your email address

### 2. Add Email Service

1. Go to **Email Services** in the dashboard
2. Click **Add New Service**
3. Choose your email provider (Gmail recommended for testing):
   - **Gmail**: Easy to set up, good for development
   - **Outlook**: Enterprise option
   - **Custom SMTP**: For production with custom domain
4. Follow the provider's authentication steps
5. Copy the **Service ID** (e.g., `service_abc123`)

### 3. Create Email Template

1. Go to **Email Templates** in the dashboard
2. Click **Create New Template**
3. Use this template structure:

**Template Name**: `ipdc_notification`

**Subject**: `{{subject}}`

**Content (HTML)**:
```html
<div>
  {{{html_content}}}
</div>
```

**Content (Plain Text)**:
```
{{text_content}}
```

4. Save the template and copy the **Template ID** (e.g., `template_xyz789`)

### 4. Get Public Key

1. Go to **Account** → **General**
2. Copy your **Public Key** (e.g., `a1B2c3D4e5F6g7H8i`)

### 5. Configure Environment Variables

Add these to your `.env` file:

```env
# EmailJS Configuration
VITE_EMAILJS_SERVICE_ID=service_abc123
VITE_EMAILJS_TEMPLATE_ID=template_xyz789
VITE_EMAILJS_PUBLIC_KEY=a1B2c3D4e5F6g7H8i
VITE_ADMIN_EMAIL=admin@ipdc.gov.et
VITE_SUPPORT_EMAIL=support@ipdc.gov.et
VITE_NOTIFICATIONS_FROM_EMAIL=noreply@ipdc.gov.et
```

### 6. Install Package

The `@emailjs/browser` package is already added to `package.json`. Install it:

```bash
npm install
```

### 7. Test the Integration

1. Start the development server:
```bash
npm run dev
```

2. Log in to the platform
3. Create a test service request
4. Check your email for the notification
5. Check EmailJS dashboard for sent emails

## Email Template Variables

Our email templates use these variables:

- `{{to_email}}` - Recipient email address
- `{{to_name}}` - Recipient name
- `{{subject}}` - Email subject line
- `{{html_content}}` - HTML body (generated by our template service)
- `{{text_content}}` - Plain text body (fallback)
- `{{from_name}}` - "IPDC Digital Platform"
- `{{from_email}}` - Your noreply email

## Notification Types

The platform sends emails for these events:

1. **Request Created** - When a tenant creates a service request
2. **Request Status Changed** - When request status is updated
3. **Request Completed** - When a request is marked as done
4. **Token Low Balance** - When token balance drops below threshold
5. **Token Allocated** - When tokens are added to account
6. **Announcements** - Platform-wide announcements
7. **Maintenance Scheduled** - Scheduled maintenance notices
8. **System Alerts** - Important system notifications

## User Notification Preferences

Users can customize their notification settings in **Profile → Notifications**:

- Enable/disable email notifications entirely
- Choose which notification types to receive
- Set email frequency (immediate, daily digest, weekly digest)
- Configure quiet hours (no emails during specific times)

## Production Recommendations

For production deployment:

1. **Upgrade EmailJS Plan**:
   - Free: 200 emails/month
   - Personal: $7/month for 1,000 emails
   - Team: $15/month for 10,000 emails

2. **Use Custom Domain**:
   - Set up SMTP with your organization's email
   - Use emails like `noreply@ipdc.gov.et`

3. **Alternative Services** (if scaling beyond EmailJS):
   - **SendGrid**: 100 emails/day free, then paid
   - **AWS SES**: Very cheap, $0.10 per 1,000 emails
   - **Mailgun**: Reliable with good free tier

4. **Monitor Email Delivery**:
   - Check EmailJS dashboard regularly
   - Monitor bounce rates
   - Review failed notifications in Firestore

## Firestore Collections

Email notifications are tracked in Firestore:

### `emailNotifications` Collection
```javascript
{
  recipientEmail: "user@example.com",
  recipientName: "John Doe",
  type: "request_created",
  priority: "medium",
  subject: "Service Request Created: Fix AC",
  templateData: { /* email data */ },
  status: "sent", // pending | sent | failed
  sentAt: Timestamp,
  failureReason: null,
  retryCount: 0,
  metadata: {
    userId: "abc123",
    requestId: "req_456"
  }
}
```

### `notificationPreferences` Collection
```javascript
{
  userId: "abc123",
  emailNotifications: true,
  notificationTypes: {
    request_created: true,
    request_status_changed: true,
    // ... other types
  },
  emailDigest: "immediate",
  quietHoursEnabled: true,
  quietHoursStart: "22:00",
  quietHoursEnd: "08:00"
}
```

## Troubleshooting

### Emails Not Sending

1. **Check EmailJS Dashboard**:
   - Verify service is active
   - Check email quota
   - Review error logs

2. **Check Browser Console**:
   - Look for EmailJS errors
   - Verify API keys are loaded

3. **Verify Environment Variables**:
   ```javascript
   console.log('EmailJS configured:', notificationService.isInitialized());
   ```

4. **Test Email Template**:
   - Use EmailJS dashboard to send test email
   - Verify template variables are correct

### Emails in Spam

1. **SPF/DKIM Records**:
   - Configure proper email authentication
   - Use verified sender domain

2. **Email Content**:
   - Avoid spam trigger words
   - Include unsubscribe link
   - Use professional formatting

### Rate Limiting

1. **Free Tier Limits**:
   - 200 emails/month
   - Max 2 emails/second

2. **Solutions**:
   - Implement email queuing
   - Use digest mode for multiple notifications
   - Upgrade to paid plan

## Security Best Practices

1. **Never commit `.env` file** - Keep API keys secret
2. **Use environment variables** - Don't hardcode keys in code
3. **Validate recipients** - Only send to verified users
4. **Rate limit** - Prevent email bombing
5. **Monitor usage** - Watch for suspicious activity
